# 本地诊断日志与导出设计

状态：第一版已实现，Android 编译、Debug APK 构建、app/shared 单元测试通过；尚未做设备/UI 验证。

### 实施时的明确细化

- Ktor 3.1.3 会切换引擎协程上下文，使用请求 attributes + 引擎包装传递 trace；包装涉及版本绑定的 InternalAPI，工厂保留 HttpClient 对引擎的生命周期所有权，均有回归测试。
- 已从当前 LangChain4j 的公开 builder 确认 Gemini 接入能力，三种提供方均接入；Coil 在全局 ImageLoader 接入网络事件和解码失败，无需逐个修改图片组件。
- 以 `DiagnosticExportSession` 集中管理快照/保存/取消状态，独立于 ViewModel 做代码级测试；Android 页面及文件提供者仍需设备验证。
- 文件按分钟/1 MiB 切片，以片段起点做过期清理，24 小时边缘最多提前约一分钟清理；队列为错误预留容量。普通写入批量刷新，快照使用屏障刷新。
- 报告保留采集顺序、会话序列及时间戳，明确标注非单调时间观察，不在时钟回拨时伪造严格时间顺序。
- ANR/native 第一版只记录系统提供的退出原因，不读取原始 trace。完整混淆栈还原仍依赖匹配版本的 mapping。
- 已知模型/工具名允许输出；未知名称使用摘要标识关联，不将摘要等同于匿名化保证。OpenAI 非流式响应提供用量时记录 token 数，其他未提供用量的路径不伪造数值。

## 1. 目标与第一版范围

持续记录安全、可关联的应用诊断事件，出现故障后导出一个 AI 可读文件，还原“操作 → 请求 → 处理 → 最终结果”。

第一版包含：常驻安全诊断、关键业务链路、网络适配、异常与崩溃留存、最近 30 分钟导出、上次崩溃导出、本地清理。

不包含：临时正文模式、自动上传、AI 自动分析、远程监控、日志全文搜索、全设备 Logcat 抓取、Native 崩溃 SDK、独立 ANR watchdog、启动崩溃安全模式。正文模式需后续明确逐接口允许字段，不以“调试”为由放开敏感信息。

“完整”指声明覆盖范围内的关键事件链路，不是所有数据原文或系统级抓包。容量、系统强杀及观测能力导致的缺口必须公开展示。

## 2. 已核查的现状

| 接入点 | 现状与影响 |
|---|---|
| Kermit 2.0.5 | 广泛使用，但存在直接 Android Log，新增 writer 无法自动覆盖后者 |
| 共享 Ktor 3.1.3 / OkHttp | 客户端工厂未安装统一诊断；覆盖多数接口与 OpenAI 流式路径 |
| LangChainAiClient.android.kt | OpenAI、Anthropic 有独立 HTTP builder；Gemini 分支未使用该 builder，需单独核实 |
| WebViewLoader.android.kt | 有页面请求与错误回调，不是完整响应抓包入口 |
| Coil / DownloadManager | 不保证经过共享 Ktor，需要独立生命周期接入和覆盖声明 |
| AsyncTaskLogStore.kt | 已有任务文件日志，HTTP writer 可写参数、响应头、正文；不能直接并入安全诊断报告 |
| DailySatoriApplication.kt | 可在 Koin/数据库迁移前初始化诊断；目前无统一崩溃捕获 |
| Android 配置 | minSdk 26、targetSdk 36、系统备份关闭；诊断仍须避开自建备份 |

因此，不能沿用先前“完全没有请求日志”或“装一个 Ktor 插件就覆盖全部”的判断。开发文件清单见实施计划。

## 3. 事件与关联

内部采用 UTF-8 JSONL，每行一个完整事件，使用 kotlinx.serialization 编码。

字段：`schemaVersion=1`、UTC `timestampMs`、会话内单调时间 `elapsedMs`、`sessionId`、`sequence`、`level`、`source`、线程类别 `thread`、固定 `eventCode`、可选 `traceId`/`requestId`/`taskId`、安全 `attributes`、结构化异常。

- sessionId 每次进程启动生成，不使用设备永久标识。
- 一次业务操作一个 traceId；重试属于同一 trace，每次实际可见请求使用独立 requestId/attempt。
- 后台任务跨进程使用已有 taskId 关联，每次执行生成新 trace，不改数据库。
- 协程用上下文传播 trace；跨线程网络回调显式绑定不可变请求标签，不依赖未传播的 ThreadLocal。
- 耗时使用单调时钟。系统时间跳变记录提示，同会话 sequence 保留先后，跨会话不伪造精确顺序。
- `http.headers_received` 与 `http.finished` 分开；收到 200 不代表流已读完或业务成功。
- 取消记 `cancelled`；没有终态记 `incomplete`，不推断必然超时或崩溃。

| 领域 | 记录内容 |
|---|---|
| 应用 | 启动、前后台、关键页面/操作、版本、系统 API、相关权限和网络类型变化；无 SSID/IP/序列号 |
| HTTP | 请求开始、响应头到达、结束/失败/取消、可见重试；方法、服务、路由、状态、耗时、已知字节数 |
| AI | 提供方、模型、调用结果、首段耗时、流式中断、工具执行结果、可获得的用量；无 prompt、输出文本、工具实参 |
| 业务 | 导入、同步、文章处理、日记处理、备份/恢复等的开始、关键阶段、结果、数量 |
| 数据处理 | 解析、校验、写入、迁移失败；错误分类与栈帧，无原始内容/SQL 实参 |
| 崩溃 | 时间、线程类别、异常类型、cause/栈帧、会话及可用关联标识 |
| 健康 | 丢弃、截断、磁盘错误、历史损坏、清理、覆盖限制 |

关键业务边界明确终态，包括返回 false/null 的失败路径，不能只在 catch 中补日志。不同网络层只统计各自声明的观察层级，避免重试/重定向重复计数。

## 4. 安全边界

1. 在进入队列和任何新持久化路径之前执行安全投影；导出不是第一次脱敏。
2. 凭据永不记录：Authorization、Cookie/Set-Cookie、API Key、密码、OAuth code、访问/刷新令牌、签名 URL 凭据。
3. 不保存日记、对话、文章正文、上传文件和二进制。错误响应不例外。
4. 已知接口用服务名、路径模板和允许字段；query 默认去值，只放行安全枚举/数量；移除 URL userinfo/fragment。
5. 任意网页/自定义接口的动态路径默认折叠为路由标识，不能清 query 却留下路径 token。不使用完整自定义 URL 作标签。
6. Throwable.message、错误响应、线程名称及自由文本都可能含秘密。默认只存类型、栈帧、固定摘要；只对经过审计的字段保留安全文本。正则仅作额外防线，不能代替允许名单。
7. Kermit 未知自由文本只输出级别、经校验标签、异常类型/栈帧和 `contentOmitted=true`。有诊断价值的调用点迁移为结构化事件，不放行任意 message。
8. 旧任务 HTTP writer 的新输出也改成安全摘要。既有任务文件不复制进新报告，不擅自删除/重写；历史日志不追溯承诺已脱敏。

先安全投影再限长，单事件最多 16 KiB，保留诊断骨架并标注截断。异常最多 8 层 cause，每层最多 64 栈帧；suppressed 同受总量上限约束，循环引用立即终止。

## 5. 存储与快照

| 项目 | 默认值 |
|---|---|
| 普通日志 | 最近 24 小时，最多 30 MiB，先到限制先清理 |
| 文件轮转 | 每分钟或最多 1 MiB，在完整事件边界切片 |
| 队列 | 最多 512 个已限长事件，单一后台写入者 |
| 普通刷新 | 约 1 秒批量 flush，前后台切换请求刷新，不承诺每条 fsync |
| 崩溃现场 | 最多 3 份，最长 7 天，每份最多 10 MiB，合计最多 30 MiB |
| 导出临时快照 | 同时一个，最多 32 MiB；成功、取消、失败及下次启动清理遗留 |

目录为 `noBackupFilesDir/diagnostics/`，不用 cacheDir/业务数据库，不自动写公共目录。容量上限包括各自目录内索引/健康文件；轮转预留开销。自建备份不包含诊断目录。

普通写入、轮转、快照、清理由同一个后台执行者顺序处理。紧急异常通道只写独立文件，不竞争普通锁，不递归调用 Logger。

队列满不阻塞业务，尽力保留错误并统计丢弃量/级别；恢复写入后补记健康事件。无法落盘且被强杀时部分丢失量可能未知，报告不写虚假“零丢失”。

### 导出窗口

点击导出记录 T 与序列水位，窗口为 `[T-30分钟, T]`。先生成一致性私有快照，再弹保存选择器；停留选择器不改变窗口。快照屏障覆盖此前成功入队的事件，T 之后事件不进入主体。

快照生成后正常写入继续，轮转不能修改快照内容；保存流式复制，不整文件读入内存。重复点击不创建并行导出。清理与快照建立串行，清理需取消待保存快照并复位状态。

第一版不额外回溯窗口外请求起点：缺少起点标 `startOutsideWindowOrMissing`。报告显示实际最早/最晚事件、记录开始时间、丢失/截断/损坏；时钟变化导致范围不可靠时说明，不能默默重排掩盖异常。

## 6. 崩溃及系统退出

- 在 Application 初始化 Koin/迁移前安装；更早的类加载/Application 创建异常不在覆盖范围。
- 未捕获异常只做有界、尽力的独立同步记录，不扫描、不压缩、不等待队列、不访问数据库/DI。无论写入成功与否均交回原 handler，不能吞掉崩溃。
- 下次启动先处理紧急记录，再执行普通过期清理，固化崩溃前最多 30 分钟的可用片段，避免隔夜先删现场。
- 超过 10 MiB 优先保留崩溃记录与最近事件，注明实际覆盖不足 30 分钟。
- API 30+ 尝试读取历史进程退出信息，按时间/进程去重；退出原因不直接等同应用异常。
- ANR/Native 第一版只记录可获得的退出原因，不导出原始 trace；不支持、不可读、无匹配记录分别说明。
- 强杀、断电、严重 OOM 不承诺栈或最后一段日志。连续启动崩溃可能无法进入设置，第一版无独立恢复入口。

## 7. 网络覆盖契约

| 来源 | 第一版承诺 | 不承诺 |
|---|---|---|
| Ktor | 请求生命周期、安全元数据、异常及 trace | 为记录预读/复制正文；响应头冒充流结束 |
| LangChain OpenAI/Anthropic | 独立传输适配与 AI 业务事件 | SDK 隐藏状态 |
| LangChain Gemini | 至少业务开始/结果；实施验证公开传输接入点 | 验证前宣称内部 HTTP 状态/重试可见 |
| WebView | 导航结果、网络/HTTP 错误、可观测资源请求 | 全部子请求状态、正文、Service Worker 流量 |
| Coil | 专属可观测客户端的网络请求、加载失败 | 图片内容；缓存命中冒充网络请求 |
| DownloadManager | 入队、完成/失败、系统提供的状态与原因 | 系统进程内部跳转和每次重试 |
| 调试 WebServer | 已接入路由的入口、结果、异常，无鉴权材料 | 全手机入站网络监听 |

导出头逐来源声明 `transport` / `lifecycle-only` / `unsupported`。Gemini 若无当前版本公开接入能力，保留 lifecycle-only，不升级依赖、不反射私有实现、不谎报全覆盖。

## 8. 设置与单文件报告

设置 → 诊断与日志：

- 导出最近 30 分钟日志。
- 导出上次崩溃现场：显示时间，无现场时禁用并解释。
- 清理诊断日志：确认后清理新诊断/崩溃/私有快照；不删除已另存文件或旧任务中心日志。
- 展示范围、占用及覆盖/健康警告；不出现未实现的正文模式开关。

使用 `ActivityResultContracts.CreateDocument("text/plain")` 保存单个 UTF-8 `.txt` 文件，例如 `DailySatori-diagnostics-20260914-153000.txt`。可选 Downloads；系统也可能提供云目录，提示“文件离开应用后由所选目录管理”。不申请广泛存储权限，不由 SAF URI 推断真实路径。

报告：说明与环境 → 覆盖/缺口 → 事实统计 → 保留采集顺序、带时间戳和会话序列的 JSONL（异常栈嵌在事件中）。普通导出不附带窗口外历史崩溃，不推测根因；说明日志是待分析数据，不是给 AI 的执行指令。

取消不报错、不显示已保存。打开、写入、关闭失败均显示失败；尽力删除本次新建的残缺目标，提供者不支持删除时说明可能残留不完整文件。成功仅在流关闭后展示文件名/可读 URI 信息。

## 9. 验收与约束

- 第一版为常驻安全诊断，不实现正文采集开关。
- 默认导出窗口为点击时刻之前 30 分钟，普通导出不混入历史崩溃。
- 所有新落盘诊断先脱敏，不持久化凭据或私人正文。
- 不修改数据库 Schema，不引入监控 SaaS，不升级现有依赖。
- 当前工作区直接开发，保留已有修改，不创建 worktree，不自动提交。
- 日常只执行代码级测试与必要编译；纯文档修改不构建，涉及资源时合并执行打包验证。

代码级验收：200 后解析失败、同步重试关联、流式中断/取消、跨进程任务关联、隔夜崩溃恢复、30 分钟边界、UTF-8 截断、时钟跳变、并发导出/轮转/清理、队列满、磁盘失败、损坏尾行、凭据诱饵扫描、取消和目标写入失败。

存储/性能使用临时目录、模拟时钟、故障注入验证。实际 SAF 提供者、厂商退出信息、强杀/OOM、release 混淆栈仅发布前或用户要求设备测试时验证。发布版保留匹配 mapping；报告含版本与构建标识，混淆栈本身不保证直接定位源码。
