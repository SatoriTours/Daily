# 个人页远程新闻入口与异步提醒 AI 解析设计

## 目标

1. 在个人页提供清晰的远程新闻入口，可查看同步规模并进入已有远程新闻设置与同步页面。
2. 提醒自然语言解析不再阻塞编辑页面；统一交给 AI 后台处理，并在成功或最终失败后通过系统通知提示用户。
3. 即使 App 退出、进程被回收或网络暂时不可用，解析请求、原始输入和处理结果也不能丢失。

## 非目标

- 不新增本地自然语言提醒解析规则。
- AI 解析成功后不自动启用提醒；必须由用户确认。
- 不替换现有提醒调度与通知策略。
- 不为提醒解析单独建设第二套后台任务框架。

## 个人页远程新闻入口

个人页“我的内容”增加“远程新闻”行，与“收藏库”“外部收藏”并列。副标题显示：

```text
已同步 N 篇 · M 个来源
```

其中 `N` 来自远程文章同步映射总数，`M` 为已启用远程新闻源数量。点击后进入现有远程新闻设置页面，用户可以查看来源、测试连接和手动同步。没有配置来源时仍显示入口，副标题为“尚未配置来源”。

## 异步解析工作流

### 提交

用户输入一段或多段提醒文字并提交后：

1. 立即持久化一个提醒解析请求，保存原始输入、时区、提交时间和请求标识。
2. 创建 `reminder_ai_parse` 异步任务并交给现有任务调度器。
3. UI 显示“已提交，解析完成后通知你”，不等待 AI 响应。
4. 相同规范化原文和时区已有活动任务时复用该任务，避免重复调用 AI。

### 后台解析

任务一次请求包含全部输入片段，要求 AI 返回带稳定 `source_index` 的 JSON 数组。后台任务依次记录以下阶段耗时：

- 任务排队等待时间；
- AI 配置读取；
- HTTP/模型响应；
- JSON 解码与字段校验；
- 草稿持久化。

日志不得包含 API Token 或完整敏感请求头。原始提醒文字只保存在应用私有数据库，不写入普通系统日志。

### 成功

AI 响应通过结构和字段校验后：

1. 保存一个待确认批次以及批次中的一个或多个提醒草稿。
2. 任务状态设为成功。
3. 发送“提醒已解析，等待确认”通知。
4. 点击通知打开对应批次确认页；用户可编辑每条草稿。
5. 只有用户确认的草稿才写入正式提醒并交给现有 ReminderScheduler。

### 自动重试

最多尝试三次：首次失败等待 30 秒，第二次失败等待 2 分钟，第三次失败后终止。

参与自动重试：

- 网络不可用、DNS、连接与读取超时；
- HTTP 429；
- HTTP 5xx；
- AI 返回临时空响应或可恢复的截断响应。

不自动重试：

- 未配置 AI；
- Token 无效或无权限；
- 输入为空；
- 已明确完成响应但结构不符合提醒协议。

进程被系统中断时沿用异步任务框架的持久化恢复机制，不额外消耗一次业务重试额度。

### 最终失败

所有可恢复重试用尽，或遇到不可恢复错误后：

1. 保存一个失败草稿批次，完整保留原始输入、时区、错误类型和最后一次错误摘要。
2. 失败草稿不进入正式提醒表，不参与定时通知。
3. 发送“提醒解析失败，点击处理”通知。
4. 点击通知进入失败草稿页，显示原文和可理解的错误信息。
5. 用户点击“重新解析”时创建新的后台任务；原失败记录保留用于诊断，新任务与旧任务建立来源关联。

## 状态模型

解析请求状态为：

```text
QUEUED -> RUNNING -> RETRYING -> SUCCEEDED
                            \-> FAILED
```

草稿批次状态为：

```text
PARSING | READY_FOR_CONFIRMATION | PARSE_FAILED | CONFIRMED | DISCARDED
```

异步任务负责执行与重试，草稿批次负责用户可见状态和原文/结果持久化。两者通过任务 ID 关联，避免把 WorkManager 状态直接当作业务数据。

## 通知与导航

新增独立的提醒解析通知类型，复用现有通知渠道设置。通知 PendingIntent 携带批次 ID，不携带原文。

- 成功通知进入对应批次确认页。
- 失败通知进入对应失败草稿页。
- App 冷启动时也必须正确恢复导航。
- 批次已确认或丢弃后再次点击旧通知，进入批次只读结果或提示“该批次已处理”，不得创建重复提醒。

## 性能策略

- 用户提交到 UI 返回只包含本地数据库写入和任务入队，不等待网络。
- 多段输入始终合并为一次 AI 请求。
- 活动任务按规范化输入、时区和本地日期去重。
- AI 输出提示保持最小字段集合，避免让模型生成解释性文字。
- 记录分阶段耗时，从实际数据判断慢点；不通过并发重复请求换取表面速度。

## 数据迁移

增加提醒解析批次和草稿持久化结构时提升数据库版本，并提供显式迁移。旧版本没有相关数据，迁移只创建新表和索引，不修改现有提醒。

建议索引：

- 批次状态与更新时间；
- 活动请求去重键；
- 异步任务 ID；
- 草稿所属批次和 `source_index`。

## 测试

必须覆盖：

1. 个人页展示远程新闻入口、来源数、同步文章数和正确导航。
2. 提交后立即返回且创建持久化任务。
3. 多段输入只调用一次 AI。
4. 重复提交复用活动任务。
5. 临时错误按 30 秒、2 分钟重试并最终成功。
6. Token 无效等永久错误不重复请求。
7. 三次失败后保存原文并发送失败通知。
8. 成功通知和失败通知在前台、后台及冷启动时正确打开对应批次。
9. 未确认草稿不产生正式提醒或系统定时任务。
10. 确认多条草稿时只创建一次且支持部分确认。
11. 进程恢复后继续待执行或待重试任务，不重复发送终态通知。
12. 日志包含阶段耗时但不包含 Token。

## 验收标准

- 点击解析后页面在本地入队完成即恢复可操作状态。
- 常规成功、最终失败都会发送且只发送一次通知。
- 通知可以可靠定位到原始批次。
- 失败原文可长期保留并手动重试。
- AI 解析成功前不会错误安排提醒。
- 个人页可以直接进入远程新闻同步管理。
