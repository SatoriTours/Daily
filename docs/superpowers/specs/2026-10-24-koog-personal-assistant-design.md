# Koog 个人助手升级方案

- 日期：2026-10-24
- 状态：方案已获用户批准实现，并要求继续一次完成；开发/验收实况见第16节。未获提交或发布授权。
- 核对基线：`7b72b743`。
- 目标：让 Daily 的 AI 从资料问答入口升级为能够接收零散信息、使用已有业务能力、持续交流的一级个人助手。
- 原则：Koog 管理解读与编排；Daily 管理事实、权限、业务数据和可靠执行。不复制文章库、提醒系统或任务队列。

## 1. 已确认需求与首版边界

### 1.1 已确认需求

1. 助手成为独立一级功能，用户可以直接聊天、交代事情、分享链接，不要求先分类。
2. 所有已发送输入先可靠保存，AI 失败不能造成记录丢失；用户仍能删除或排除记忆用途。
3. 用户主动分享的链接复用现有本地文章收录；明确待办复用现有提醒。
4. 使用 Koog 替换聊天中的关键词意图判断和手写 Agent 循环，由模型决定查什么、如何追查和调用哪些工具。
5. 助手可广泛查询现有非敏感业务数据，而不是只限文章或日记。
6. AI Key、X 凭据和其他认证信息不提供给模型；隔离由访问层执行，不依赖提示词。
7. 助手可以在现有数据库保存自己的记忆、摘要、关联和运行状态。
8. 继续使用现有云端模型配置；本地 Agent 不等于本地大模型。
9. 手机后台允许延迟与中断，但记录不能丢、恢复不能重复执行成功动作；不承诺永久常驻。

### 1.2 首版交付内容

- 一级助手入口、自然对话、跨会话查询和可打开的来源。
- 广泛的安全数据查询、现有文章收录、现有提醒创建与查询。
- 原始记录、可重建索引、来源明确的长期记忆、纠正与遗忘。
- 稳定动作标识、部分成功恢复、任务中心关联及备份迁移。

### 1.3 明确不做

- 手机端大模型、embedding 服务、知识图谱、多 Agent 系统。
- 任意 Shell、文件系统访问、任意 SQL 或自动操作其他 App。
- 自动发送消息、付款、改变认证配置或安装扩展。
- 默认把聊天复制进日记或点子；首版查询这些内容，新增或修改后续另行设计。
- 助手批量修改、删除其他业务记录。删除助手消息和遗忘记忆属于首版管理能力。
- 自动追踪网页内全部链接、主动推送推荐、跨设备同步和独立服务器。

## 2. 现状与需要替换的部分

| 当前位置 | 已有能力 / 问题 | 本次处理 |
|---|---|---|
| `McpAgentService.kt` | 手写工具循环、流式最终回答、失败回退 | 由 Koog 接管编排；迁移后不保留两套正常执行引擎 |
| `AiSearchOrchestrator.kt` | 用关键词判断来源与时间，中文切词、固定排序 | 移除聊天主路径的硬编码意图路由；查询执行、分页和证据结构保留并整理为工具 |
| `McpToolRegistry.kt` | 日记、文章、书籍、记忆、只读 SQL、外部 MCP；提醒仅草稿 | 复用业务实现，重新封装受控工具；不直接继承无限扩展的 SQL 权限 |
| `McpAgentPrompts.kt` | 强制三段式回答、工具选择规则较固定 | 改为按意图自然交流；权限不能靠提示词实现 |
| `AiChatViewModel.kt` | 保存消息；模型请求由页面协程启动 | ViewModel 只提交命令和观察状态，不拥有可恢复任务的生命周期 |
| `ChatConversationRepository.kt` | 分会话保存文本、引用和步骤 | 作为原始对话的事实来源，补稳定消息身份和生成状态 |
| `MemoryExtractService.kt` | 主要从内容生成短摘要，当前输入有截断 | 扩展聊天索引和可追溯记忆；长文分段，不把开头摘要当全文依据 |
| `AsyncTaskRunner` / `AsyncTaskWorker` | 持久任务、租约、检查点、重试、启动恢复 | 继续使用；Koog 检查点从属于业务任务，不新建调度系统 |
| `SaveArticleTaskHandler.kt` | 调用已有网页收录流程 | 补文章 ID、附言、准确状态等结果契约，不另写抓取器 |
| `ReminderRepository` / 提醒协调器 | 创建、防重身份、生命周期及通知调度 | 提取页面与 Agent 可共用的业务入口，不能只插入数据库行 |
| `SecretFieldRegistry` | 已登记多个密钥和加密载荷字段 | 作为隔离依据之一；并不足以自动判定所有字段都可提供给 AI |

注意：`AiConversationSessionStore` 当前保存的请求会话 ID 主要用于请求关联，不能当成已经把历史对话传给模型。

## 3. 总体架构与职责

```text
助手界面 / 显式分享入口
        │
        ▼
原始消息 + assistant_turn 持久任务（同一事务）
        │
        ▼
现有 AsyncTaskRunner（唯一运行调度者）
        │
        ▼
KoogAssistantRuntime
  ├─ 上下文装配：近期原文 + 版本化摘要 + 有效记忆
  ├─ 模型理解、工具选择、结果处理、自然回答
  └─ 请求预算、取消、检查点和界面事件
        │
        ├─ AiService 适配器 → 当前配置的模型接口
        │
        └─ 受控工具
             ├─ SafeDataGateway → 现有 SQLDelight / Repository
             ├─ AssistantMemoryService → 记忆与索引
             └─ AssistantActionService → 动作记录 → 文章 / 提醒业务服务
```

以上组件名称是职责说明，不是已经存在或已锁定的 Koog API。首版不为每项职责建立独立模块或通用插件平台；优先在清晰的包边界内实现。

- Koog 只决定意图、查询和工具调用，不拥有数据库驱动、密钥仓库或任意网络访问权。
- 业务层决定参数是否合法、动作是否允许、是否已经执行，以及实际结果是什么。
- 任务层决定何时执行和重试；Koog 不再建立独立常驻循环。
- 数据层保存可恢复事实；UI 流式事件不是唯一状态来源。
- 同一会话的执行串行，复用现有任务租约和前置依赖；不同会话也不能同时执行同一动作。

## 4. 数据读取：广泛覆盖，但不提供原始数据库权限

### 4.1 安全业务目录

提供 `list_data_sources` 返回安全业务数据源、可用字段、关系和查询能力。它不是原始 `sqlite_master`，不列出密钥字段或受保护载荷的真实结构。

每个现有表和字段都必须明确归类为：

- 业务可读；
- 经类型化投影后可读；
- 仅本地业务服务可用；
- 不向助手暴露的内部数据。

这不是把读取范围固定在少数业务表，而是对全部现有 Schema 做覆盖登记。新增字段或表默认不自动开放，迁移时补分类；测试发现未分类项即失败。

### 4.2 当前库的覆盖方案

| 数据范围 | 向助手提供什么 | 不提供什么 |
|---|---|---|
| `article`、`tag`、`article_tag` | 标题、正文、附言、标签、日期、收藏与处理状态 | 含凭据的原始 URL、内部错误载荷 |
| `book`、`book_viewpoint`、读书 AI 会话与消息 | 书籍、笔记、用户反馈、已保存讨论；标明作者和用户/AI角色 | 未完成的内部请求、调试内容 |
| `diary`、续写版本/汇总、月总结 | 整串原文、日期、标签、汇总及依据；避免把续写重复计数 | 仅把旧摘要视为事实，不读取私有文件路径 |
| `diary_attachment`、`image` | 关联 ID、类型、已有转写和安全元信息 | 任意路径读取、二进制文件、未授权媒体识别 |
| `weekly_summary`、`unified_news_summary/source` | 已保存总结、引用及来源 | 用总结替代发生冲突的原始记录 |
| `idea_topic` 及来源、事件、会话、消息 | 主题、进展、原始资料、用户反馈、讨论总结 | 把 AI 建议当成已确认决定 |
| `reminder`、`reminder_profile/event`、提醒解析批次与草稿 | 内容、日期、重复规则、当前状态、调度结果及用户可见草稿 | 原样内部 metadata、未过滤的解析载荷 |
| `memory_entry`、`chat_conversation` | 依据权限和遗忘状态返回记录；区分用户与 AI | 已删除、已排除的内容；把 AI 回复当用户事实 |
| 外部收藏项与远程文章同步记录 | 标题、正文、公开来源、关联文章、同步状态 | 原样 `debug_json`、`normalized_json`、服务端错误正文 |
| `external_favorite_source` | 来源名称、账号展示信息、启用及同步状态 | `auth_json`；原样 `config_json`、错误载荷 |
| `ai_config`、`mcp_server`、`skill_config`、`remote_news_source` | 模型/服务显示名称、启用状态、能力及配置是否齐全 | Token、认证信息；原样配置 JSON、请求头、含凭据地址 |
| `setting` | 逐个登记的安全设置，例如主题、模型分配、用户授权开关；用户文稿按业务适配器解析 | 整表查询、备份密码、语音配置中的凭据、微信读书 Key、认证与权限载荷 |
| `async_task`、`async_task_batch` | 类型、阶段、进度、安全错误码、关联对象 | 原样 payload、checkpoint、result、原始错误文本 |
| `session` | 不暴露；技术登录会话不是用户资料 | 登录、认证和会话安全数据 |
| `sms_reminder_source`、`phone_message`、`bookkeeping_entry` | 首版不开放内容查询；已有提醒可从提醒工具读取 | 加密载荷及解密结果，不绕过金融正文/手机消息既有隐私边界 |
| FTS 虚表和其内部表 | 经业务搜索工具间接使用 | 原始内部表、系统 Schema、绕过字段策略的查询入口 |

生活资料在数据库外独立加密保存，继续保持不进入普通聊天、自动记忆与 MCP 的既有边界。此次“广泛读数据库”不隐含解除上述保护。

### 4.3 查询协议

首版不向模型提供原始 SQL 工具。采用统一的类型化查询：

- `query_data(source, fields, filters, order, page)`；
- `aggregate_data(source, filters, group_by, measures)`；
- `search_records(query, source_types, time_range, cursor)`；
- `read_record(ref, section, cursor)`。

字段、操作符、聚合函数和关联关系来自安全目录；值使用参数绑定。跨源关联只走已登记关系，不允许把用户文本、表达式或字段名直接拼成 SQL。时间边界由本机按输入时区转换为绝对时间。

这样仍能查询全部已授权业务范围，而不需要依靠正则解析 SQL 来防止别名、子查询、联合查询、系统函数或嵌套 JSON 绕过。

旧 `query_local_database` 不注册给新 Agent；其实现可留给未迁移调用者，但不能成为新路径的后门。若后续确需原始 SQL，必须单独设计隔离执行环境，不能直接放开当前数据库。

### 4.4 密钥隔离与外发边界

最低隔离清单包括：

- `ai_config.api_token`；
- `mcp_server.api_key`；
- `skill_config.api_token`；
- `remote_news_source.api_token`；
- `external_favorite_source.auth_json` 中的 X 等访问/刷新凭据；
- `setting` 中的备份密码、微信读书 Key、语音配置、认证状态等敏感值；
- 配置 JSON、URL、请求头及错误信息中潜在的 Cookie、Authorization、签名和 Token。

采用安全字段正向投影，不是读取整行后再让模型忽略。配置混合 JSON 只导出类型化安全字段，未知字段不透传。模型只拿“凭据已配置/未配置”，网络层内部使用真实凭据。

工具出口、错误、引用、可观察日志和 Koog 追踪统一使用安全结果；不能先在框架日志中记录原始数据再脱敏。禁用默认记录完整请求/响应的调试插件。

私有路径、鉴权 URL 使用不可逆猜测的引用句柄在本地解析；模型不能通过更换 URL、记录类型或 ID 越权读取。URL 收录继续走现有网络安全约束，不因 Agent 入口允许访问本机服务或任意协议。

“允许读取”意味着相关片段可能发送给用户选定的云端模型，首次启用需要清楚说明；不等于允许把全文发给远程 MCP、搜索服务或第三方工具。远程 MCP 仅沿用已启用来源，默认只发送最小外部查询，不自动夹带私人上下文。

结构化凭据字段可以强制隔离；用户手工粘贴到日记、正文或聊天的任意未知密钥，不能承诺全部自动识别。对明显凭据进行模型侧遮蔽，但明确保留这一残余风险，不把模式匹配当安全保证。

## 5. 助手写入权限：能保存自己，但不能任意改库

| 写入目标 | 入口与限制 |
|---|---|
| 原始消息、最终回复 | 宿主持久化，模型不能覆盖原始用户记录 |
| 会话摘要、助手笔记、个人记忆 | 类型化记忆工具；必须有来源、性质和版本；支持用户修正 |
| 索引与关联 | 后台整理服务；可重建，不能替代原始事实 |
| 执行检查点、动作结果 | 宿主记录；模型不能伪造“已完成”、抹掉防重记录或改变权限 |
| 本地文章 | 现有收录业务接口；创建或复用，不能用 SQL 修改 |
| 提醒 | 共用创建/查询业务接口，保存、调度和权限结果分别报告 |
| 其他业务表、配置、凭据 | 首版无写权限 |

不提供 `execute_sql`、任意键值写入设置表或“修改自己的任意表”工具。用户能管理自己的记忆，不等于模型能修改审计、权限或安全策略。

## 6. 原始记录、索引与记忆

### 6.1 三种长期数据与一种执行数据

1. **原始记录**：已发送用户输入、最终助手回复、来源时间及已有附件引用。流式未完成回复标明状态，不进入事实记忆。不同角色必须保留。
2. **检索索引**：摘要、主题、实体、事件时间、来源关联及全文检索。可以失效和重建。
3. **个人记忆**：明确事实、偏好、目标、当前项目、用户纠正；每条可回到具体原文。
4. **执行检查点**：任务进行到哪里及已完成动作。它不是个人事实，也不是聊天的唯一副本。

Markdown 适合助手笔记与摘要正文；身份、有效状态、来源和关系存结构化字段。不维护一个持续追加的大 `memory.md`。

### 6.2 Koog ChatMemory 的接法

Koog 的历史组件接入宿主数据库，恢复时由宿主选择有效原文窗口与摘要。库的具体接口由锁定版本确定，不在本设计假定签名。

- 用户消息在调用模型之前保存，不能依赖 ChatMemory 成功结束一轮后才保存。
- Koog 压缩只改变模型上下文，不改写或删除原始聊天。
- 保存回调按稳定消息身份合并最终回复，不能全量替换原始日志或重复插入消息。
- 工具轮次记录在运行检查点/动作记录中，按需恢复；不当作用户说过的话。
- 来源删除、权限变化或版本变化后，装配上下文时必须重新校验，不能直接加载旧检查点跳过网关。

### 6.3 自动整理规则

- 原始输入提交后立即具备基础检索能力；AI 整理可稍后完成，失败不影响原文可查。
- 一轮稳定后将会话标记为待索引，复用持久任务做增量处理；同一来源版本合并任务，不逐次重扫全部历史。
- 明确“记住这个”优先处理；普通输入提取摘要与关联，有依据的稳定表达可形成事实记忆，AI 推断先作为候选。
- 只有用户当前明确表达和有效原文能作为个人事实依据。收藏文章、引用别人观点、助手回答和工具说明不是用户立场。
- 敏感身份凭证、金融原文等不自动沉淀为核心记忆。
- 长内容分段建立索引，保留原文位置与版本；不能截取前几千字后声称覆盖全文。
- 用户纠正优先于旧归纳；冲突旧记忆退出当前有效状态，必要时保留变化历史。

### 6.4 遗忘与删除

区分三个动作并在 UI 中说明：

- **不用于记忆**：原始记录保留，但不用于长期提取和历史召回；当前仍展示的对话窗口不偷偷删除。
- **忘掉某条记忆**：失效相关记忆，并保存最小的来源/主题排除标识，阻止后台重建；不删除对应文章、日记或提醒。
- **删除原始记录**：清理原文、派生索引、引用、相关摘要和检查点中的副本；已创建业务对象默认保留，删除前清楚说明。

排除按来源版本管理；新输入有相似内容不自动解除遗忘，只在用户明确要求重新记住时恢复。删除后的失效处理由数据库状态先行保证，物理清理可重试；在清理完成前，查询和上下文装配也不能返回旧内容。

无法撤回已经发送给云端服务商的历史请求，旧离线备份也不会被远程擦除；对用户明确说明。

## 7. 检索与交流方式

### 7.1 每轮上下文

- 当前用户输入、接收时间、时区、明确选择的资料；
- 最近完整对话窗口；
- 较早对话的有依据摘要；
- 少量有效个人记忆与用户修正；
- 本轮通过工具获取的相关证据。

不强制每轮搜索日记或其他私人数据；普通交流可直接进行。统计事实必须查库，不能从摘要估算。

### 7.2 检索过程

模型理解意图 → 生成查询/同义表达和范围 → 查询候选 → 按需读原文 → 判断依据是否充分 → 回答并引用。

- 替换旧的关键词分流、固定中文截词和固定来源优先级。
- 保留 FTS/参数化查询、排序、分页和时间过滤。初筛由数据库完成，模型只重排有限候选。
- 对话中的“这个/上次那个”结合近期消息与已关联对象解析，不凭空猜 ID。
- 所有引用由工具返回的有效引用句柄生成，并在输出时校验；不能由模型编造可打开 ID。
- 提醒、文章状态等易变信息读取当前业务对象，不使用旧记忆当最新状态。
- 搜索无结果只能说明本次范围未找到；有限改写后仍不足时直说，不断言历史从未发生。

### 7.3 首版默认预算

- 每轮最多 5 个模型—工具循环；其中检索改写最多 2 次。
- 搜索默认每页 20 条，接口硬上限 100 条；正文按片段读取，单次上限 8,000 字符，提供续读游标。
- 模型上下文按实际上下文窗口预留输出与工具预算，不把“保留全部”理解成“全部发送”。
- 网络超时沿用现有配置，并设单轮总截止时间。只保留一层负责网络重试的策略，不叠加 Koog、AiService 和 Worker 形成倍增重试。
- 达到预算时保留已完成结果，说明未完成部分；不能为了生成漂亮答复继续无限调用。

预算是初始上限，不是性能承诺；用真实接口测试校准。首版不承诺严格语义召回；同义表达测试不足时单独提出 embedding 增强，不悄悄增加新服务商。

## 8. 工具目录与执行规则

### 8.1 首版工具组

| 工具组 | 作用 |
|---|---|
| 数据目录与查询 | 安全目录、跨业务搜索、类型化查询、聚合统计、读原文 |
| 助手记忆 | 查记忆、保存有依据的笔记/事实、修正、按用户要求遗忘 |
| 本地文章 | 提交/复用收录，查询处理状态与文章入口 |
| 现有提醒 | 创建、查询、读取状态；不修改提醒默认规则 |
| 外部资料 | 仅使用已经启用且允许的现有 MCP，不能自行配置新服务器 |

工具具有明确的只读/写入属性。来源文本一律是数据，网页、历史消息和工具结果中的“请调用某工具”不能自动成为当前用户授权。

### 8.2 链接收录

- 用户主动分享链接默认收录；明确“别保存，只看一下”时遵从当前指令。文中引用的其他 URL 不自动收录。
- 原始输入保存链接和附言；Agent 使用本地引用指向原链接，含签名 URL 不原样进入模型。
- 复用已有文章身份与规范化规则；只去除已有规则确认可去除的跟踪参数，不擅自合并不同资源。
- 收录返回关联文章 ID 和持久子任务 ID；已有任务直接关联，不重复排队。
- 分别显示“已接收链接”“原文已保存”“AI 整理完成/失败”。抓取或整理失败不能统称保存成功。
- 附言与原始消息关联必须保留，即使现有收录方法暂不支持 comment；适配时补齐而不是丢弃。

### 8.3 提醒创建

- 明确指令且必要字段清楚时，直接通过现有业务入口创建，替代聊天中只生成待确认草稿的旧规则。
- 日期、时区基于收到原始指令的时刻解析并固定；后台次日重试不能把“明天”再往后移动。
- 没有具体通知时间，采用现有无截止/无定时待办语义，不私自指定 9 点；内部兼容字段不得造成即时误通知。
- 关键日期、对象或重复规则不明确时，只追问缺失部分；新回复关联原动作后继续，不再次创建已成功动作。
- “以后可以考虑”只是想法；引文、假设与否定表达不能被当作创建授权。
- 保存、防重、权限检查、通知调度共用同一业务入口。存库成功但权限不足或调度失败时，准确报告并只补调度，不重建待办。
- 首版保留现有提醒强度、安静时段和完成规则，不借 Agent 改写通知策略。

### 8.4 多意图示例

输入：“保存这篇文章，明天下午三点提醒我看，再找找以前类似的东西。”

1. 原话与输入时间落盘。
2. Koog 识别收录、提醒、检索三个意图，业务层分别校验。
3. 收录和提醒分别建立稳定动作记录；可先建提醒，附文章关联稍后补齐。
4. 工具返回当前实际状态。检索和聊天不必等待耗时的文章全文整理。
5. 回答：“收录处理中；提醒已加入；找到两条相关记录。”并提供现有页面入口。
6. 文章处理结束后更新同一结果关联，不重复追加一个任务或把原话改成“全部成功”。

## 9. 持久任务、动作防重与恢复

### 9.1 状态所有权

- `async_task` 是执行、租约、重试与取消的唯一调度真相。
- `assistant_action` 是动作身份、业务对象和执行结果的记录，不是第二套任务队列。
- Koog 检查点是可恢复的上下文快照，不是“是否真的创建了提醒”的唯一证据。
- UI 观察持久状态；应用进程内事件仅用于及时刷新。

每条已接受消息对应稳定 turn 身份。若持久任务等待用户补充，任务执行可以结束为已处理，但 turn 保留等待状态；用户回复时继续关联动作。子任务尚未结束时，父轮不占住 Worker 等待，而是保存关联并允许当前回答结束。

### 9.2 动作状态

`planned → submitted → succeeded / failed`；必要时 `needs_input` 或 `cancelled`。

`submitted` 仅表示业务已接受或子任务已排队，不等于实际完成。文章整理、提醒调度的细分状态从其现有业务对象读取。

### 9.3 防重原则

- 执行前保存由宿主分配的动作身份、规范化参数、参数指纹和目标引用；不能只依赖模型可能重生成的 tool call ID。
- Koog 恢复时先加载已执行结果，不让模型自由重排并再次执行全部写操作。
- 同一 turn 对同一已提交意图的重放映射到原动作；不同输入中的明确新意图不能因为文本一样而被全局去重。
- 提醒沿用稳定创建 ID 与 `createConfirmedOnce` 等已有能力；文章沿用现有身份查找和收录防重。
- 纯数据库效果与动作关联尽量同事务写入；跨服务步骤按稳定 ID 检查已有效果再补记录，不能只看动作表有没有写完。
- 不确定上次执行结果时先核查，不盲目重建。模型补发参数不同的同一动作必须重新校验，不能套用旧完成状态。
- 部分成功只恢复失败/未提交动作；流式失败只恢复回答，不重新执行整轮 Agent。
- 取消后不提交新动作；已成功创建的业务对象保留并显示，不能承诺自动回滚。

### 9.4 后台限制

按 Home/锁屏不主动取消已接受任务；系统仍可暂停或回收。复用 WorkManager 与现有启动恢复，必要时遵循现有前台任务通知规范，不能靠隐藏常驻服务保活。

强行停止、关机、断网和省电限制可能阻止及时执行；展示等待/失败原因。无网络时输入可落盘，已明确的本地查询可用；不伪装 Agent 已完成联网分析。

## 10. 数据模型与迁移建议

具体列类型在实施前按现有 SQLDelight 约定确定，设计只规定必要责任，不预先铺开通用知识图谱。

| 数据 | 最小建议 |
|---|---|
| `chat_conversation` 扩展 | 稳定 `client_message_id`、turn 关联、消息生成状态、记忆/召回许可及来源版本；旧消息原文保留 |
| 新增 `assistant_session` | 会话身份、摘要及覆盖消息范围/来源版本、上下文失效版本；原始历史仍在聊天表 |
| 新增 `assistant_action` | 稳定动作 ID、来源消息/turn、动作类型、规范化参数与指纹、状态、目标引用、子任务 ID、安全错误码 |
| `memory_entry` 扩展 | 性质、有效状态、结构化依据、来源版本、用户修正/提取策略版本；正文可用 Markdown |
| 新增 `assistant_memory_exclusion` | 最小的来源/主题排除标识，用于遗忘后防止重新提取；不保存被遗忘原文副本 |
| 现有 `async_task` 扩展类型 | `assistant_turn`、`assistant_index`；检查点中保存版本化 Koog 状态和安全引用，不增加另一套运行租约 |
| 全文索引 | 聊天与笔记补可重建索引；现有文章/日记/记忆 FTS 继续使用，内容更新与删除同步失效 |

索引先复用现有 `memory_entry` 内容类型和来源关联，不另造一个完整资料副本。多条依据以受限结构化引用保存；发现确需独立多对多关系时再拆表。

迁移必须同步递增 Schema 版本、补迁移脚本，验证旧记录、既有提醒及关联保留。历史消息逐步建立索引，不在启动时阻塞全量调用 AI。

所有持久数据与当前加密数据库/备份体系一致；不把 Key 写入 Koog JSON、导出文件或打包资源。运行快照记录 Koog/格式版本，版本不兼容时保留原文和动作记录、重建模型上下文，而不是重复执行动作。

恢复旧备份后，先核对来源、对象、动作身份及快照版本。不自动重放未核清的写入动作；标为可继续并由用户恢复。现有提醒自身的恢复调度继续走原流程，不能再让 Agent 创建一次。

## 11. 模型适配、依赖和迁移边界

### 11.1 接入策略

首选 Koog 执行器/客户端适配现有 `AiService`，保留接口地址、协议、模型分配、思考控制、请求会话标识和隐私诊断。其他文章处理、日记等 AI 功能不随本次一起重写网络栈。

工具轮次、结果角色、流式最终消息、取消和错误映射需要明确测试；不能把 Koog 需要的工具结果降成普通字符串后丢失语义。

实现优先使用适合 KMP 的 class-based tools；不依赖 JVM 反射注解作为共享接口。Koog 平台依赖根据实际正式版本支持放在可用 source set 内，不能把 JVM-only 依赖强塞入 `commonMain`；必要时在 `androidMain` 实现运行适配，保持公共业务契约。

继续沿用现有功能模型分配：交互走快速交互；新索引任务走经济后台处理；用户主动要求深度回顾时才用深度总结。不新增一页逐工具模型配置，也不自动切服务商或备用模型。

### 11.2 必需的兼容性门槛

当前工程 Kotlin `2.1.21`、Ktor `3.1.3`、JVM target 17、Android minSdk 26。Koog 当前文档的 Kotlin 要求比本工程新，且不同模块的平台支持不同；不能直接写一个 `latest.release` 就宣布可用。

实施的第一切片必须锁定正式发布版本，验证：

- 工具、流式、历史和持久化模块的 Android 兼容性；
- Kotlin 元数据、Ktor、协程与序列化依赖冲突；
- 现有客户端适配是否覆盖已配置服务商的基本工具/流式流程；
- R8/打包、包体与必要的内存影响。

本设计不预先指定未经验证的版本号，也不把 develop 分支的依赖当正式版要求。可能需要 Kotlin/Ktor 联动升级；若必须提高 minSdk、改变 AGP/发布要求或大幅迁移无关模块，应先报告新增取舍，不静默扩大范围。若无可用组合，结论为阻塞，不擅自退回 Pi 或另一套模型。

### 11.3 旧逻辑退出

新路径验收后，移除助手对旧关键词路由、固定三段式回答和手写 Agent 循环的依赖。底层查询与其他仍在使用的业务函数不为“清理”而删除。

不在失败时静默切回旧引擎重新执行整条指令。版本回退是交付层操作，需保证已产生数据的迁移兼容，不是运行中的第二次写入机会。

## 12. 一级入口与交互设计边界

推荐底部导航为“今日｜日记｜助手｜读书｜我的”；保留现有默认启动页和各功能入口，不因当前 `AI_CHAT_TAB_INDEX` 与“我的”复用索引就继续把身份绑定在一起。

- 助手页以消息为主体，不叠加大量仪表盘卡片。
- 顶部提供会话及记录/记忆管理；正文支持原文、来源和简洁结果入口。
- 随手记录短回应，讨论可展开，不强制每次都写总结。
- 文章、提醒显示实际阶段；低频诊断放任务中心，不把工具日志全部铺在聊天中。
- “停止生成”与“取消未执行动作”区分，避免用户以为停止文字就撤销了提醒。
- 管理页清楚区分删记录、不用于记忆、遗忘，以及是否保留关联业务对象。
- 国际化、字号、间距、颜色沿用项目主题。实现前使用真实长内容做布局稿；设计稿不等于 App 视觉验收。

此次仅确定入口和信息层级，不在方案阶段改动 UI 或启动模拟器。

## 13. 分阶段实施与验收

阶段顺序不表示每阶段各自算整个任务完成。第一切片先确认依赖可用，后续按已批准范围连续推进。

| 阶段 | 产出 | 必需验收 |
|---|---|---|
| A. 接入与安全网关 | 锁定版本、现有 AI 适配、完整数据分类与类型化查询 | Android 编译/打包；流式与工具往返；所有当前表字段有分类；密钥不能进入任何模型出口 |
| B. 可靠记录与对话 | 原子接收消息/任务、会话上下文、只读检索、引用 | 跨会话/同义/指代；统计准确；AI 失败输入仍在；删除后上下文不复活 |
| C. 业务执行 | 本地文章、提醒、动作身份、后台与部分成功恢复 | 多意图；重复投递；各断点中断；结果与业务状态一致；不误通知 |
| D. 记忆与交付 | 增量索引、修正/遗忘、一级入口、迁移备份 | 原文依据；排除防重提取；旧库升级/恢复；UI 和受影响功能回归 |

### 13.1 功能与失败矩阵

| 类别 | 必测场景 |
|---|---|
| 密钥隔离 | 安全目录无密钥字段；请求非法字段、类型伪装、JSON、URL、错误路径不能泄露；用哨兵凭据检查模型输入、结果、日志和快照 |
| 查询边界 | 非法源/字段/操作符、伪造引用、跨类型 ID、系统表、旧 SQL 工具绕过；所有写 SQL 不可达 |
| 广泛查询 | 文章、日记整串、书籍与笔记、点子、历史消息、提醒、总结、收藏均有代表性用例；被保护载荷明确拒绝 |
| 语义与时间 | 换说法找回、上次/那个指代、按日期筛选；相对日期固定在接收时区；资料不足不编造 |
| 链接 | 新收录、已有文章、附言保留、抓取失败、AI 整理失败、同一资源重试、不递归收录文中链接 |
| 提醒 | 明确时刻、无定时待办、缺信息追问、引文/否定不误建；权限缺失、调度失败；沿用现有通知规则 |
| 执行可靠性 | 写入前后各断点中断、流式失败、重复投递、并发提交、取消、文章成功提醒失败；最终业务对象不重复 |
| 记忆 | 用户事实与外部/AI观点区分；新纠正覆盖旧归纳；旧提取任务不能覆盖新版本；遗忘后重建不复活 |
| 迁移与备份 | 旧库原文、提醒和设置保留；新表/索引可用；检查点版本不兼容可安全重建；恢复不重放未核清动作 |
| 体验 | 普通聊天无需强制检索；断网已接收提示真实；结果可打开；长内容/主题/窄屏/状态/滚动不遮挡 |

### 13.2 验证方式

- 单元测试使用假模型、假工具和临时数据库验证边界与状态机，避免把每条失败矩阵都变成付费请求。
- 使用 `.local/ai-test.json` 做少量新增的助手真实接口用例：组合指令、跨轮指代、查询改写和工具结果回答。不用提醒解析测试替代助手编排测试，不打印密钥。
- 按变更运行聚焦测试，稳定后合并执行相关模块测试和必要编译；涉及依赖/打包配置时执行 `assembleDebug`。
- 计划最终代码级命令：`./gradlew :app:compileDebugKotlin :app:assembleDebug :app:testDebugUnitTest :shared:testDebugUnitTest`，按实际受影响范围与缓存证据调整，不对同一未变快照重复全套。
- 日常不启动模拟器；UI 实际交互/视觉证据在发布前或用户明确授权设备测试时补齐。缺证据就标未验证，不能用代码测试代替。
- 遵守当前项目的主会话自测与审查约定；不因这份设计自动派生 Agent、创建 Workspace 或执行 Git 交付。

## 14. 决策与尚待验证项

### 14.1 推荐决策

1. Koog 替换意图路由与 Agent 编排，不替代数据库、索引和业务校验。
2. 广泛读取安全业务投影，而不是直接开放数据库句柄或依赖正则限制的 SQL。
3. 助手状态存现有数据库；原文、记忆与动作结果各有明确所有权。
4. 文章和提醒使用现有服务，只补业务入口和结果契约；后台调度也复用现有体系。
5. 首版以现有云端模型＋全文/整理索引完成闭环，不同时引入本地模型和向量基础设施。
6. 权限、来源真实性、防重和遗忘由程序执行；模型只能在边界内理解与建议。
