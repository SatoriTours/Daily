# 批量提醒解析与确认设计

## 目标

允许用户在“提醒我什么”输入框中一次描述多项事务，解析为多张独立提醒草稿，选择后批量保存。输入过程不调用 AI；远端回退最多按一次显式解析触发一次请求，不能按条目逐次收费。

## 输入与拆分

- 用户通过“解析提醒”按钮显式提交；输入变化本身不解析。
- 首先按换行、分号、编号列表以及能够确定为事项边界的句号拆分。
- 不按普通逗号机械拆分，避免将日期、补充条件和提醒内容拆成不同事项。
- 每个片段保留原始顺序与索引，用于合并本地和远端结果。
- 空片段、纯标点和完全重复的片段在解析前去除。

## 本地优先与费用边界

1. 每个片段先进入现有确定性本地解析器。
2. 本地能够完整识别的片段直接产生草稿，不调用远端。
3. 所有本地无法完整识别的片段合并为一次严格 JSON 数组请求。
4. 一次用户点击最多产生一次远端请求；禁止对每个片段分别调用 AI。
5. 缓存键包含规范化输入、当前本地日期和时区。相同上下文再次提交直接复用结果。
6. 远端响应必须带原始片段索引；缺失、重复或越界索引视为该片段解析失败，不猜测映射。

## 数据模型

- `ReminderBatchInterpretation`：批次 ID、规范化输入、按原始顺序排列的结果和批次级错误。
- `ReminderBatchItem`：稳定 item ID、source index、原始文本、`ReminderDraft`、是否需要确认、条目错误、选择状态和保存状态。
- 单条输入也返回包含一个 item 的批次，不保留另一套单条 UI 状态机。
- 稳定 ID 由批次 ID 与 source index 生成；保存成功后记录已创建 reminder ID，防止重复点击产生重复提醒。

## 编辑与确认界面

- 解析结果显示为独立草稿卡，保持输入顺序。
- 每张卡显示内容、日期/重复方式、首次提醒时间和实际行为摘要。
- 用户可以展开编辑、删除草稿或取消勾选。
- 默认选中所有有效草稿；解析失败的条目保留原文、默认不选中，并允许手动补齐。
- 主操作显示“保存选中的 N 条”；没有有效选中项时禁用。
- 保存前不会写入提醒仓库，也不会调度通知。

## 批量保存

- 保存按 item ID 逐条执行，并复用现有单条确认、持久化和调度逻辑。
- 采用部分成功语义：成功项标记完成并从待保存区域移除；失败项保留其编辑内容和错误。
- 已成功 item 再次提交时跳过，不重复创建。
- 页面关闭前若仍有未保存草稿，显示放弃确认。
- 保存结束后显示“成功 X 条，失败 Y 条”；全部成功时返回提醒列表。

## 错误处理

- 远端不可用：本地成功项仍正常展示；未解析项保留原文并允许手动编辑。
- 远端数组部分损坏：只拒绝损坏元素，合法元素继续使用。
- 日期或重复规则冲突：条目标记需要确认，不自动保存。
- 保存或调度失败：沿用现有安全语义，保留草稿并显示对应错误；已成功条目不回滚。

## 测试与验收

- 多行、分号和编号输入按顺序拆分；逗号补充条件不被误拆。
- 全部本地命中时远端调用数为 0。
- 多个未命中片段只产生 1 次远端调用。
- 本地与远端结果按 source index 正确合并。
- 缓存命中不产生额外远端调用。
- 可取消选择、删除、编辑草稿，保存数量随选择变化。
- 部分保存失败时，成功项不重复创建，失败项保留。
- 单条输入继续正常工作。
- 真机验证键盘、长列表滚动、旋转/进程恢复和通知调度。

## 非目标

- 不在输入过程中自动解析。
- 不把多个事项合并成一个提醒。
- 不为每个事项单独调用远端 AI。
- 本阶段不支持跨设备共享尚未保存的批量草稿。
