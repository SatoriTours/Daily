# 手机助手

Android 的短信与选定应用通知统一接入手机助手，分别识别待办和账目。一条来源可有多个待办与一条账目候选，各结果独立确认、忽略和重试。原待办、账目与人工修改保留；iOS 仍仅保留接入方案。

## 处理边界

- 短信、通知分别配置接收开关、待办、账目和脱敏 AI 授权。升级沿用短信待办、通知记账原设置，新用途默认不开启；全新安装两个来源均关闭。
- 只保存候选信息，验证码、普通聊天、广告、应用自身通知、分组汇总不进入来源流水。已支付与未执行的取货等动作按分句识别；明确交易本地入账，未完成交易和日期、金额不明的结果待确认。无明确截止时间的待办不设置定时提醒。
- 同一来源事件正文更新增加修订号；已生成或已忽略的待办仅按相同内容、明确动作同义词匹配，不按分句位置覆盖不同动作或业务编号。异步处理必须校验修订号、授权代次及结果状态，关闭、忽略或人工修改后旧结果不得写回。
- 开启短信接收且权限可用时，默认短信应用通知只跳过短信已开启的用途，仍处理通知独有用途；其他相近账目沿用疑似重复核对，不能仅凭金额自动合并。
- 同一通知的身份在内容、时间更新与监听服务重建后保持稳定；移除后再次发布建立新身份。只持久保存系统标识的哈希与随机事件身份，重连清理已不活跃的身份，不扫描历史正文。
- 待办与待确认结果查询不受最近记录数量限制；最近处理每次加载 50 条，可继续加载更早记录。
- 通知被清除不代表业务取消；已有支付结果不会自动完成仅金额相同的待办。来源记录能关联同一消息生成的待办与账目，用户可核对后完成事项。
- 删除来源正文只清除原文，保留结果和防重身份；忽略待办不影响账目。失败按结果重试，不重做成功项。

## 实施顺序与验证

1. 增加分句待办识别、来源模型和加密来源仓库，Schema 30 → 31，验证旧数据库数据保留。
2. 增加统一服务与持久任务；复用现有待办确认、日期提取、脱敏 AI 和记账引擎，验证四种来源／用途组合、混合内容、多待办、更新、授权失效及独立操作。
3. 修改两个 Android 采集入口，统一手机助手页面、来源设置、待确认／待办／账目及最近处理入口，保留旧导航兼容。
4. 验证相关模块测试、Kotlin 编译与资源打包；修改 AI 输入或解析时运行少量真实脱敏接口测试，不启动模拟器。
