设计说明（对照 docs/07 杂志风标准）

改动设计决策现状问题
编辑性导语下一次提醒作为封面标题（kicker + 大字 + 时间用主色），30 天统计降为小字辅助；替换现在的统计胶囊「未来 30 天 · N 个」统计胶囊，信息弱、仪表盘感
文本式模式切换最近 / 月份 / 已结束 用文字 + 下划线指示；「已结束」带小圆点提示FilterChip 药丸排一排，控制感重
分组标题小型大写 + 字距，今天/明天 用主色强调；右侧安静计数纯 labelLarge 一行小字
杂志式条目日期前置为「大日号 + 星期」块（今天的主色强调），标题两行、元信息一行，行间发丝线分隔；状态/重复是小徽章灰底圆角卡片堆叠，标题+meta 两行文字，无层级
月份模式年份居中 + 十二个月横向 rail：当前月圆点、有提醒显示数量、选中用主色容器；下方直接展开当月条目（沿用现有 expandedMonth 逻辑，仅重绘）3×4 格子 + Badge，统计看板感强
详情编辑移入底部弹层（grabber + 分组标签 + 属性 chips + 文字按钮），列表保持纯阅读；危险操作「删除」独立红色编辑表单内嵌在列表中间，TextButton 横排拥挤
筛选筛选同样移入底部弹层，chips 分组，底部主按钮显示结果数顶部下拉 Surface 面板，遮挡列表
颜色边界主色只用于：下划线、今天、时间、选中态、FAB；大面积保持纸面—
待你确认的 3 个点：
1. 详情编辑改底部弹层（②），还是保留内嵌展开？推荐弹层，列表更干净，改动集中在 ReminderListScreen。
2. 「月份」模式的月条目区：设计稿用「月 rail + 下方展开」；也可以改成整页按月分节的纵向列表（更像杂志目录），你更喜欢哪种？
3. 已结束条目是否需要支持「重新启用」操作（设计稿暂未放）。
