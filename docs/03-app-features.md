# Daily Satori 应用功能说明

> **重要**：本文档是 AI 助手理解应用功能的核心参考。在修改代码前，请先阅读相关模块的说明，确保不会破坏现有功能。

## 应用定位

**Daily Satori** 是一款**本地优先的智能知识管理工具**，帮助用户：
- 快速收集和整理网页内容
- 记录日常思考和感悟
- 管理阅读书籍和书摘
- 通过 AI 助手与知识库交互

## 通知红点

红点表示有待处理或待确认的事项，进入列表与详情后继续标出原因及处理入口。任务中心仅对最近 24 小时内尚未确认、也未被后续同一任务成功记录解决的失败显示红点；执行中的任务显示普通进度提示。任务详情可确认并消除红点，确认状态持久保存，失败记录与诊断信息仍可查看。提醒红点通过完成本次提醒消除；思想整理失败在详情显示原因，并提供重新整理入口。

## 本地诊断与日志

设置中的「诊断与日志」支持导出最近 30 分钟日志、导出上次崩溃现场和清理本地诊断。

- 保存为单个 UTF-8 文本文件，通过系统保存界面选择 Downloads 或其他目录，不申请广泛存储权限、不自动上传。
- 记录脱敏的网络元数据、关键业务阶段、异常类型/栈帧和应用生命周期；不默认记录正文、凭据或任意自由文本。
- 普通日志最多约 30 MiB，按分钟/大小切片、保留不超过约 24 小时；崩溃现场最多 3 份、7 天，每份 10 MiB。
- Ktor、LangChain 和 Coil 有传输事件；WebView、系统下载及调试服务器只承诺可观测范围，具体覆盖/缺口写在报告内。
- 强杀、系统限制、容量清理可能造成缺失；ANR/native 只记录可获得的退出原因，不自动收集原始系统 trace。
- 清理不影响已导出的文件和旧任务中心日志。临时完整正文模式、自动 AI 分析和云端监控不在第一版范围。

## 文章模块

### 核心功能

- **一键收藏**：从其他应用分享链接到 Daily Satori
- **智能解析**：自动提取标题、正文、图片
- **广告过滤**：内置 ADBlock 规则
- **离线缓存**：全文和图片本地存储
- **Markdown 渲染**：优化排版体验
- **AI 解读**：生成文章摘要和要点
- **解读结构**：新闻按“新闻事实 → 为什么重要（分析）→ 工作／技术决策（分析）”展示，教程与观点等文章使用“核心内容”。仅在原文明示时展示事件时间，保留未确认信息和条件；来源链接由应用使用真实原文地址补充。长文先提取各段事实，再统一分析，避免把分段推断当作事实继续扩写。
- **处理速度与完整性**：先在本地保存完整原文，正文 HTML 转 Markdown 不调用 AI；中文正文保持原文，英文全文另行分块翻译。标题和摘要完成后立即更新页面，全文翻译和独立封面下载不阻挡已保存内容的阅读。
- **长文与失败恢复**：摘要覆盖全部正文分块后合并，译文保护原始代码和链接；成功分块持久保存，原文或模型配置变化时失效，重试复用未变化的成功结果。AI 失败保留原文和成功结果，显示失败／重试状态，不把原文兜底标记为 AI 成功。外部收藏整理复用相同分块流程。

### 数据模型 (SQLDelight)

```sql
-- shared/.../sqldelight/DailySatori.sq
CREATE TABLE article (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT,
    ai_title TEXT,
    content TEXT,
    ai_content TEXT,
    html_content TEXT,
    ai_markdown_content TEXT,
    url TEXT UNIQUE,
    is_favorite INTEGER DEFAULT 0,
    comment TEXT,
    status TEXT DEFAULT 'pending',
    cover_image TEXT,
    cover_image_url TEXT,
    pub_date INTEGER,
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);
```

## 日记模块

### 核心功能

- **时间线展示**：按日期分页显示
- **搜索功能**：全文搜索日记内容
- **标签筛选**：按标签过滤日记
- **语音日记 AI 整理**：编辑器中每段已转写录音可手动整理，用「快速交互」模型去机械重复、理顺明确的表达并补标点、分段，不作摘要或扩写。先预览、核对替换目标，再确认并保存；原始转写独立保留，可查看、恢复，多次整理始终使用原始转写。仅自动定位唯一完整录音文字块，正文改动或目标不明确时要求用户重新选择，避免覆盖手写内容。每次采用均保留独立版本，可对各版填写修改意见；意见随日记保存，再生成时提供原始转写、选定的采用版及其意见，并参考最近5条历史意见。本次意见优先，明确事实纠正以用户意见为准，含糊内容不猜测；不同日记、不同录音不共享意见。正文撤销/重做不删除后续意见及版本历史。版本和意见保存在现有设置表，兼容旧采用记录，随备份保留，不修改数据库结构。
- **AI 自动标签**：保存新日记或修改正文后，使用默认 AI 在持久后台任务中提炼通常 1–2 个、最多 3 个重点标签；优先复用日记独立词库和已确认别名。候选新标签独立复核同义关系，不确定的名称进入待确认列表，不自动加入词库。手动标签优先，同次编辑中删除的标签即使正文改变也不补回；生成失败保留原标签，过期结果不写入。
- **便捷调整标签**：点日记卡片标签可直接打开调整面板；编辑器可直接删除，面板支持常用标签点选、替换、设为重点固定保留及 AI 重新生成，并可撤销最近 20 步标签调整。调整随日记保存生效。
- **标签管理**：日记筛选入口及设置 → 日记标签均可管理。可关闭自动打标、为无标签历史日记补标、确认新名称、让 AI 仅分析标签名称并建议同义合并。合并前预览影响篇数，保留旧名称作为搜索别名，支持撤销最近一次合并并保留无关词库新增；受影响日记或别名有后续修改时阻止撤销以保护新内容。统计使用轻量标签索引增量更新，标签来源仅在打开相应日记时加载。词库、来源及删除记录保存在现有本地设置表，随数据库备份保留。
- **我的思想**：日记页顶部入口，基于已保存的日记正文持续整理价值观、做事准则、思维方式和变化；每条附可点击的原文依据，并区分明确表达与 AI 归纳。支持保存自己的补充与修正、手动重试更新。
- **思想档案更新**：应用运行时观察日记变化，由持久后台任务分段读取全部正文，缓存未改变的提取结果；退到后台或锁屏不主动暂停，通知显示整理进度，系统中断后从已保存断点续作。修改、删除日记时移除失去依据的条目。使用「深度总结」模型配置，失败保留仍有依据的旧内容，应用重启后补做更新；档案与用户修正保存在本地键值存储。
- **用于 AI 对话**：思想档案页可开关（默认开启）。流式和普通回答均可参考最新且有日记依据的归纳，并显示可打开的原日记引用；最新用户修正单独提供，旧档案不会覆盖当前表达。日记变化导致档案过期时跳过旧归纳；统计查询保持原有 SQL 检索流程。

## 生活档案 (`ui/feature/lifearchive/`)

- 「我的」页面提供独立入口；保存域名、订阅、支付等资料，支持自定义类型、长按重命名/删除并迁移资料。
- 搜索默认收起，点击图标展开，仅在本地搜索标题、类型、正文和动态字段；关闭时清空搜索。
- 文字输入由「快速交互」云端 AI 整理成动态字段；编辑可「再说一段话」让 AI 优化，保留未涉及信息，标记字段变化，确认后保存。字段名、值、分类及正文也可手动修改。
- 「从待办导入」分批分析续费、订阅类待办，展示草稿和来源；确认保存时检查来源/档案版本。同来源重复导入更新已有档案，原待办和提醒保持原样，失败批次可重试，已生成草稿保留。
- 原文和当前编辑资料会发送给所选 AI，无脱敏；请求不附带普通聊天、记忆或其他档案值，错误不回显服务端正文。
- 完整资料和类型清单通过 Android Keystore AES-GCM 加密，保存到 `noBackupFilesDir/life_archive/` 的独立原子快照；参与应用密码加密备份，跨设备恢复后使用新设备密钥重新加密，不进入数据库、自动记忆或 MCP。首次保存提示换机、卸载或清除数据前先完成备份并保留密码；已有旧备份不会自动补入资料。
- 未保存输入、草稿及来源描述仅驻留页面内存；离开取消 AI 请求，进程结束后需重新输入。
- AI 结构化返回兼容单个 JSON 代码块包装，同时严格校验类型、字段、数量及来源 ID；纯文本和截断 JSON 仍视为失败。待办解析复用同一包装处理。

## AI 功能模块

### 手机助手

设置 → 手机助手统一短信与通知入口。两个来源分别配置接收、待办、账目与脱敏 AI 授权，通知可选择来源应用；全新安装默认关闭接收，升级沿用原短信待办与通知记账配置，不自动开启新增用途。页面分为待确认／待办／账目，最近处理入口可核对候选来源、重试失败项、补建结果、屏蔽来源和清除原文。候选及正文加密保存并参与现有备份，记账在本机解析，不上传金融正文。

明确交易自动入账；缺少金额、多个金额、币种不明、未确认完成或疑似重复进入待确认列表，支持确认、编辑、忽略和删除。类型与完成状态只根据交易正文判断，商户名称、备注与还款日不作为判断依据；带符号金额不自动取绝对值，单独的 `$` 不猜测为美元。相同通知事件及同来源的可靠交易号用于防重，金额相同且时间接近仅提示疑似重复；人工确认结果及删除／忽略记录不会因同一交易的新通知被重建，明确冲突的账号尾号不会自动合并。删除／忽略保留加密身份记录，清除原文和商户。各币种按通知接收月份分别统计收入、支出和退款，转账、还款及待确认项不计入收支。系统限制、隐藏内容、强行停止应用或来源未发通知仍可能漏记。

iOS 尚未实现，面向 iOS 27 的后续接入方案见 [iOS 手机助手实施方案](./ios-notification-bookkeeping.md)。来源模型与处理边界见 [手机助手](./phone-assistant.md)。

#### 待办识别与处理

- 短信与通知都能生成待办和账目；一条来源可包含多个待办及账目候选。已支付与未执行的取货等动作按分句处理，不能因为含已完成支付就跳过整条信息。不读取或补回历史短信、通知。
- 本地筛选充值、缴费、续费、取件、预约等候选，跳过普通聊天、已完成交易和验证码。验证码不保存、不上传；原短信和发送者使用本机密钥加密保存，随现有加密备份机制恢复。
- AI 请求只接收脱敏正文：所有数字、账号、卡号、余额、金额、链接与邮箱先遮蔽。发送者不提供给 AI；含姓名、地址、身份凭证或不支持文字体系的短信仅在本地生成通用事项，不把私密正文写进待办。提供脱敏预览，远端错误不回显服务端正文。
- 明确事项自动添加；付款含义、截止时间不明确或已过期时进入待确认。每个待办独立确认、忽略或重试；相同事件正文更新不会重做已确认／忽略的结果。待办接入现有提醒列表，支持查看和手动完成。同一信息的账目与待办保留关联，支付不自动完成仅金额相同的事项。
- 期限在本地提取，明确未来日期和时刻才用于定时；不猜测「明天」的具体时间。待确认时可输入未来截止时间，或留空创建不带定时提醒的待办；保留旧待办的原提醒规则。
- 创建时仅显示应用内数量提示，未完成时在截止前两小时提醒；临近截止才创建时提醒一次。截止时刻不随时区变化，安静时段仅静默通知，完成／截止后停止。支持编辑截止时间、查看原文、忽略、屏蔽发送者、失败重试及重新调度。
- 后台任务仅保存来源 ID，接收与排队、结果关联以事务保存。每种来源有独立授权代次，旧异步结果在关闭、撤销用途、修改正文或人工处理后不得写回；重试只处理未完成结果。开启短信且接收权限可用时，默认短信应用的镜像通知仅跳过短信已开启的用途，通知独有用途继续处理。
- 通知内容与显示时间更新沿用同一事件身份，移除后重新发布建立新身份，重连保留仍活跃的身份。待办及待确认查询不受最近记录数量限制，最近处理按 50 条分页加载。
- AI 未授权或正文不能安全脱敏时使用本地通用事项；AI／处理失败保留候选与已成功的其他结果，可在最近处理中单独重试。清除原文不会删除待办、账目或防重身份，清除后不再自动处理本条信息。强行停止应用、权限或省电限制仍可能造成遗漏。

### 1. AI 聊天 (`ui/feature/aichat/`)

**功能描述：**
- **智能对话**：与知识库进行自然语言交互
- **MCP Agent**：AI 自动调用工具搜索日记/文章/书籍
- **记忆系统**：三层记忆（核心偏好、内容摘要、对话历史）
- **Markdown 渲染**：AI 回复支持格式渲染
- **记忆搜索**：独立记忆搜索面板，支持全文搜索和重建

**交互流程：**
1. 用户输入问题
2. AI 自动检索相关记忆作为上下文
3. AI 调用工具搜索知识库
4. AI 生成结构化答案（Markdown 格式）
5. 显示搜索引用来源

**文件结构：**
```
ui/feature/aichat/
├── AiChatScreen.kt     # 聊天界面 + 记忆搜索面板
└── AiChatViewModel.kt  # 状态管理 + 对话持久化

shared/.../service/mcp/
└── McpAgentService.kt  # MCP Agent 核心（工具定义、执行、结果汇总）

shared/.../service/memory/
└── MemoryExtractService.kt  # 记忆提取服务（AI 摘要 + 全量重建）
```

### 2. AI 配置 (`ui/feature/aiconfig/`)

**功能描述：**
- 模型管理：添加、编辑、删除 AI 模型配置
- 多 Provider 支持：OpenAI、DeepSeek、Anthropic 等兼容 API
- 默认配置：标记一个配置为默认使用，标题生成、自动标签、记忆提取等小功能继续使用默认模型；语音转写仍使用独立语音设置。
- **功能模型分配**：设置 → AI 模型 → 功能模型分配，仅列三类；从已保存的模型配置中选取，或「跟随默认模型」，不按每个小功能分别配置。
  - **快速交互**：聊天、主动输入／待办／资料整理、日记润色与补充知识、点子对话，突出响应速度。
  - **经济后台处理**：URL／新闻摘要与翻译、日记中的链接摘要、X 等外部收藏整理、新闻机会分析，适合低成本模型和异步处理。
  - **深度总结**：思想归纳、读书感悟与总结、周报、日记月总结、点子总结与方案沉淀，优先思考质量。
- 分配保存在现有设置表，随备份保留；未配置、旧备份中的无效选择和删除已分配的非默认模型均回到默认配置。失败不自动换模型或服务商；现有结果不因修改分配自动重算，后续请求使用当前选择。
- DeepSeek 官方及 OpenCode Go 的 DeepSeek 请求按用途控制思考：前两类关闭思考，深度总结开启思考，V4 系列另指定高推理强度。其他服务商不发送不兼容参数，深度和延迟取决于所选模型及服务商原生能力；页面不承诺固定速度、费用或通用推理开关。

### 3. 记忆系统

**架构：**
```
memory_entry 表 (SQLDelight)
├── type='core'     # 核心偏好/事实（手动添加或自动提取）
├── type='content'  # 内容摘要（从日记/文章/读书笔记提取）
└── type='chat'     # 对话记忆（从聊天中提取关键信息）
```

- **自动提取**：添加日记/收藏文章时自动调用 AI 提取摘要
- **手动搜索**：记忆搜索面板支持全文检索
- **全量重建**：一键从所有现有内容重新生成记忆
- **对话注入**：每次 AI 对话自动检索相关记忆作为上下文
